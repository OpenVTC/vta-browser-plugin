Start from a known state

If you have been through this before, or a previous reviewer left the agent mid-flow, reset it first. This clears the agent's login profiles and contexts and puts it back to the state these instructions assume. It affects the demo agent only.

After a reset, any wallet already connected to this agent — including one you set up a moment ago — is no longer known to it, and you start again from step 1.

1. Install the wallet

Install the extension. A setup tab opens by itself. If you closed it, open the extension's popup and click Open setup.

The wallet asks for no site access when it installs. It asks for one site at a time, later, at the moment it needs each one.

2. Point it at the demo agent

In step 1 of the wallet's setup, paste the Agent DID from the top of this page and click Prepare. Chrome asks for access to the agent's host — approve it, or the wallet cannot reach the agent.

The wallet then shows a command, because normally a person who runs the agent would run it. Here, this page runs it for you.

3. Authorise your wallet

Copy the whole command the wallet is showing you — it looks like pnm acl create --did did:key:z… --role admin --expires 1h — and paste it below. Pasting just the did:key:z… works too.

The authorisation is granted for 7 days rather than the one hour the command asks for, so it does not expire underneath you mid-review.

4. Connect

Back in the wallet, click Connect. Setup finishes and the wallet shows the agent as connected.

The passkey lock offered during setup is optional. If you would rather not enrol an authenticator on your machine, leave it off — everything below still works.

5. Sign in with the wallet (SIOPv2)

Sign out of this site, then sign back in using Sign in with your VTA Wallet. The wallet proves control of your DID to the agent, and this site verifies the result with the agent rather than trusting the browser.

The first time, the wallet is invisible to this page until you enable it: open the extension's popup and choose Enable on this site. That is the per-site grant — the wallet does not appear on any page you have not approved.

No cookie is written at any point in this flow. The extension holds no cookie permission at all; the site receives a signed token it verifies for itself.

6. See the approval prompt on its own

This is the control the extension exists to provide, so it is worth seeing deliberately rather than in passing. The button below does what any relying party can do: it asks your agent to carry out a task — here a harmless, read-only one (…).

The wallet stops it and asks you first. The prompt names this site as the asker and names the task; the site supplies neither. It is drawn by the wallet in its own window, so the page cannot restyle it, dismiss it, or answer on your behalf.

Click Deny the first time. The request fails and this page is told only that you refused — which is the useful thing to verify. Then try again and approve.

The wallet is not available on this page yet — open the extension's popup and choose Enable on this site first.

A task your agent's policy gates goes one step further: the agent works out the real effects itself, and asks an approver to confirm them against a digest — never the description the site supplied. That second round needs an approver enrolled, which is more than this demo sets up; the prompt you see here is the first round.

If something goes wrong

  • "Connect" fails after authorising. The authorisation is tied to the exact did:key in the command the wallet showed you. If you clicked Prepare again, the wallet minted a new one — copy the new command and authorise again.
  • The wallet cannot reach the agent. Chrome's site-access prompt was probably declined. Open the extension's popup and enable the agent's host, then retry.
  • Anything else. Reset the demo agent above and start from step 1.
